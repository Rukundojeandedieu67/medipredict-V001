# MediPredict data pack

## What is in this folder
| File | Purpose |
|---|---|
| `data_inventory_and_gaps.csv` | Every dataset the project needs: what exists, what is untrusted, what is **missing**, who likely holds it, and which phase uses it. Start here. |
| `readings_template.csv` | The canonical daily stock file. This is the single most important missing dataset. |
| `facility_blood_bank_registry_TEMPLATE.csv` | One row per facility: has a blood bank?, fridge capacity, beds, maternity beds. |
| `deliveries_log_TEMPLATE.csv` | Order and receive times from regional centres or drones. Replaces the tuned lead-time assumption. |
| `transfers_log_TEMPLATE.csv` | Past hospital-to-hospital transfers. Needed to validate rebalancing. |
| `sample_readings_30d_SIMULATED.csv` | 30 days x 30 districts x 8 groups (7,200 rows) generated by a simple simulator. **Not real.** For testing the upload flow only. |
| `test_inputs/` (and `test_inputs.zip`) | Deliberately messy files for testing the upload and mapping screen. All data in them is simulated or fake. |

Rows marked `EXAMPLE-001` in the templates are placeholders; delete them before sending a file.

## How to get real data (priority order)
1. **Daily stock readings** (closing stock, units issued, units received, expired, and units requested but not available) from hospital blood banks, or from the regional blood transfusion centres' dispatch records. Even a spreadsheet export from a register is enough; the upload layer maps column names.
2. **Unmet demand / stockout records.** Without this, the model cannot be trained on real data, only scored.
3. **Delivery logs** (ordered, dispatched, received times) to replace the tuned lead times.
4. **Facility registry** (fridge capacity, beds) and **transfer history**.
5. Ask the source of `blood-bank.csv` to correct the blood group columns before it is used.

Send no patient-level data. Aggregate daily counts per blood group are all that is needed.

## How much real data is enough to train?
The retrain command refuses to run with fewer than 100 positive labels (a node-group-day followed by unmet demand) in the training split. Rough sizing:

`series-days needed = 100 / stockout-day rate`

Real stockout-day rates are unknown. If the rate were 0.1% (an assumption, not a measurement), you would need about 100,000 series-days for training alone, which is roughly 30 districts x 8 groups x 420 days. Hospital-level data across more sites reaches this faster than district-level data. Until then, use the model only to **score** real uploads as a ranked watch-list, and treat results as unvalidated.

## Rules
- Uploaded data is labelled `entered`, never `real`, until the source is documented.
- Never mix simulated rows into a "real" training file. Keep them in separate files and report which was used.
- Do not describe the system as predicting stockouts accurately. It produces a ranked watch-list, validated so far only on simulated data.
